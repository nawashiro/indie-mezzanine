# Design

## Context

動機と変更範囲は `proposal.md`、外部から観測できる振る舞いは `specs/landing-page/spec.md` を参照する。

現在のルートページは `internal/relay/landing.md` をgoldmarkでHTML化し、`internal/relay/landing.go` が文書枠とWebmention発見用の `link` 要素を加えて返す。ページには見出しと説明、外部リンクがあるが、MF2のクラスは出力していない。

## Goals / Non-Goals

**Goals:**
- 既存のMarkdown正本と表示内容を維持したまま、生成されるHTMLを一つのMF2エントリーとして解釈可能にする。
- エントリー名に既存の主見出しを使い、説明とリンクを本文に含める。
- WebmentionエンドポイントのHTML要素とHTTP Linkヘッダの既存挙動を維持する。

**Non-Goals:**
- Webmentionの受付、投稿資格、保存、フィード出力の変更。
- 外部のwebmention.appへの実リクエストを必須とするテスト。
- READMEや投稿例の変更。

## Decisions

### 既存のページ構造にMF2の意味づけを追加

生成文書内で既存の主見出しに `p-name` を与え、ページ説明を `e-content` に含め、その全体を一つの `h-entry` として出力する。ページ本文やリンク順序を複製せず、現在のMarkdown描画経路を維持する。

見出しを別途追加して二重表示にする方法や、Markdown正本に生HTMLを埋め込んでレンダラーの挙動へ依存する方法は採らない。MF2クラスの付与は生成側で一貫して行う。

### 生成HTMLを契約として検証

既存のランディングページテストを拡張し、出力に単一の `h-entry`、名前として認識される主見出し、本文として認識される説明とリンクがあることを検証する。併せて従来のWebmention発見情報やページ説明が保たれることを確認する。

外部webmention.appへの接続をテスト条件にしない。MF2のクラス・構造と抽出可能な内容をローカルで検査し、ネットワークや外部サービスの可用性からテストを独立させる。

## Risks / Trade-offs

- [HTMLの見た目や既存の説明構造を変えるとページ表示を損なう] → 既存Markdownを正本として維持し、MF2の属性とコンテナだけを追加する。契約テストで既存見出しとWebmention発見情報を確認する。
- [MF2クラスだけを確認しても、本文やリンクがエントリーに含まれない可能性がある] → テストで名前・本文・本文中リンクの関係を検証する。

## Migration Plan

保存データや公開APIに変更はない。新しいバイナリを配備すればルートページのマークアップが切り替わる。問題があれば以前のイメージへ戻せる。
