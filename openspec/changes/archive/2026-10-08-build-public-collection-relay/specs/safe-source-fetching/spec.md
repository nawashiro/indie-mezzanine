# Spec Delta

## Purpose

公開リレーは信頼しない送信者のURLを取得する。取得処理は内部ネットワークへのアクセスと過剰な資源消費を防ぐ。初回URLだけでなく、名前解決とリダイレクトを含む実際の接続経路を検査する。

## ADDED Requirements

### Requirement: 接続時の取得先検査
リレーはHTTPとHTTPSだけを取得する SHALL。リレーは許可ポートを明示する SHALL。リレーは実際の接続先IPを検査し、ループバック、プライベート、リンクローカル、その他の非公開用途アドレスを拒否する SHALL。リレーはIPv4とIPv6の等価表現を扱う SHALL。

#### Scenario: 内部アドレスへの通知
- **WHEN** sourceが内部IP、メタデータ用リンクローカルIP、IPv6ループバック、IPv4-mapped内部IPを指定する
- **THEN** リレーは接続前に取得を拒否する
- **AND** 対象のHTTPサーバーはリクエストを受け取らない

#### Scenario: 公開名が内部IPへ解決する
- **WHEN** sourceのホスト名が内部IPへ解決する
- **THEN** リレーは接続前に取得を拒否する

#### Scenario: DNS応答の変更
- **WHEN** 新しい接続時の名前解決結果が許可IPから拒否IPへ変わる
- **THEN** リレーは新しい接続を拒否する

### Requirement: リダイレクトの同等検査
リレーは全リダイレクトでスキーム、ポート、URL内の認証情報、接続先を検査する SHALL。リレーはリダイレクト回数に有限の上限を設ける SHALL。リレーは内部IPへのリダイレクトを拒否する SHALL。

#### Scenario: 認証情報付きのLocation
- **WHEN** 取得先がuser:passwordを含むLocationを返す
- **THEN** リレーは転送先へリクエストする前に取得を拒否する
- **AND** リレーはBasic認証を送らない

#### Scenario: 許可しない取得先への転送
- **WHEN** 取得先が内部IP、許可外ポート、または非HTTPスキームへ転送する
- **THEN** リレーは転送先へ接続しない

#### Scenario: リダイレクトループ
- **WHEN** リダイレクト数が設定済み上限へ達する
- **THEN** リレーは取得を失敗として終了する

### Requirement: 取得資源の有限化
リレーは取得全体の時間、読み込む展開後本文サイズ、同時取得数に有限の上限を設ける SHALL。リレーは上限を超える本文を解析または保存しない SHALL。リレーはContent-Lengthだけを上限判定の根拠にしない SHALL。

#### Scenario: 圧縮または長さ不明の本文
- **WHEN** gzipやチャンク転送の本文が展開後のサイズ上限を超える
- **THEN** リレーは読み込みを打ち切る
- **AND** リレーはその取得から投稿を保存しない

#### Scenario: 遅いサーバー
- **WHEN** サーバーがヘッダーまたは本文を時間上限内に返さない
- **THEN** リレーは取得を打ち切る
- **AND** リレーは処理資源を解放する

### Requirement: 取得経路の一元化
リレーはWebmention処理とmf2解析に同じ取得済み本文を使う SHALL。リレーは検証中の短縮URL解決、著者の別ページ取得、環境プロキシによる検査迂回を行わない SHALL。リレーは原本HTMLを永続ログへ出力しない SHALL。

#### Scenario: 短縮リンクと外部著者
- **WHEN** ページが短縮URLと外部の著者URLを含む
- **THEN** リレーはそれらを検証の補助として取得しない
- **AND** リレーは元ページ内のリンクとmf2だけを使う

#### Scenario: プロキシ環境変数
- **WHEN** 起動環境がHTTP_PROXYまたはHTTPS_PROXYを設定する
- **THEN** リレーはその設定を外部取得へ自動適用しない
- **AND** リレーは接続先検査を維持する
